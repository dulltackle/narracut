# 04 — 准备真实文案与代表性样片

Type: task (HITL)
Status: open
Blocked by: —

## Question

把那条仪器操作演示视频的真实文案和几段代表性实拍片段放进仓库，作为整个开发的测试夹具。

需要用户提供：

1. **完整中文文案**，逐句拆好（20 句以内）→ `fixtures/script.md`
   每行一句，就是将来 Script Table 里的一行。
2. **3–5 段代表性实拍片段**（不需要全部 20 段）→ `fixtures/clips/`
   「代表性」的意思是必须至少包含：
   - 一段**明显长于**其对应旁白的
   - 一段**明显短于**其对应旁白的
   - 一段时长和旁白**大致相当**的

   文件名标注它对应文案里的第几句。

## 为什么它挡在时间模型前面

「素材短于旁白就冻最后一帧」这条规则，只有看到真实素材的时长分布才知道它是**罕见的兜底**还是**天天触发的常态**。

如果多数实拍片段都短于旁白，那冻帧就会成为这条片子的主要观感——那这条规则就不成立，时间模型要重新设计（比如改成慢放、或者提示用户补拍）。这个判断没法靠推理，只能看真实数据。

## 顺带要记录的：素材的编码格式

02 号票查明，素材编码不合规会让 Remotion 在 Player 和 renderer 两侧 fallback 到**不同的组件**，直接破坏「Preview = Render」。手机和相机很可能产出 HEVC/H.265 而非 H.264，也常见可变帧率（VFR）。

所以拿到样片后，对每一段跑一次 `ffprobe`，记下：容器、视频编码、音频编码、分辨率、帧率（以及是否 VFR）、色彩空间。

这决定 09 号票要不要引入自动转码——如果你的设备本来就出 H.264 CFR，那一整块工程量可以省掉。

## 产出

文件落到 `fixtures/`，在本票 `## Answer` 里记下：每句旁白的字数、每段素材的实际时长、两者的初步对照，以及上面那份 `ffprobe` 结果。

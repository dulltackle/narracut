# 09 — 素材导入规格与转码策略

Type: grilling
Status: open
Blocked by: 04

## Question

素材允许什么编码进来，不合规的怎么办？

02 号票查明：`@remotion/media` 的 `<Video>` 在两端行为一致，**但遇到 CORS 或不支持的编解码器时会 fallback，而两端 fallback 的目标不同**——Player 退到 `<Html5Video>`，renderer 退到 `<OffthreadVideo>`，两者行为不一致（官方自己举了循环播放的例子）。这是「Preview = Render」唯一一道真实裂缝，而它**完全可以靠控死素材编码来堵住**。

现实压力：手机和相机拍的素材很可能是 **HEVC/H.265**，不是 H.264。这不是边缘情况，是常态。

要定的：

1. **支持编码白名单**：容器 / 视频编码 / 音频编码 / 色彩空间 / 帧率各自允许什么。目标是让 `@remotion/media` 永远走主路径、永不 fallback。
2. **不合规素材怎么处理**：
   - A. 直接拒绝，提示用户自己转码——最省事，但把麻烦丢给用户，而用户就是你自己
   - B. 导入时自动转码成规范格式，原件保留、转码副本入项目——体验好，但引入 ffmpeg 依赖、转码耗时、磁盘占用翻倍
   - C. 只警告不拦截，让用户自己承担预览与成片不一致的风险——最差，违背 Preview = Render
3. **选 B 的话**：ffmpeg 从哪来（系统依赖？打包？Remotion 自带的那个能不能复用）、转码参数、转码时机（导入时阻塞还是后台）、副本存哪、DSL 里引用原件还是副本。
4. **变帧率素材**：手机常出 VFR（可变帧率），落到 30fps 合成上会不会漂。要不要在导入时统一转成 CFR。
5. **导入时的完整性校验**：02 号票建议打开项目时校验素材存在性，报错要给出「Scene ID + 相对路径 + 尝试解析的绝对路径」。这个校验和编码校验合并成一步。
6. **分辨率与宽高比**：素材不是 16:9 或不足 1080p 时怎么办（拉伸 / 留黑边 / 裁切 / 拒绝）。

## 依赖说明

- **04** 提供真实样片，用 `ffprobe` 一看就知道你的拍摄设备实际产出什么编码。如果本来就是 H.264 CFR，这张票的答案会简单很多；如果是 HEVC 或 VFR，B 方案基本是必选项。

## 产出

结论回填本票 `## Answer`。若选 B，转码参数要给出可直接运行的 ffmpeg 命令行。
支持编码白名单要写进 `CONTEXT.md`，它会同时约束 06（DSL 要不要记录编码信息）和 07（转码在哪个进程跑）。

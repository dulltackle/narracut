# 候选预览、审阅与输出交互原型

状态：用户已明确选择 A「视频＋审阅抽屉」。仅为可丢弃原型，不连接生产后端。

## 运行

在仓库根执行：

```sh
python3 -m http.server 43104 --bind 127.0.0.1 --directory plugins/narracut/prototype-review-light
```

打开 http://127.0.0.1:43104/ 。URL 参数 `?variant=A`、`B`、`C` 选择结构；底部深色区域是原型工具，不进入产品界面。

## 决策依据

用户已确认先看候选视频，视频占主要空间；辅助信息要组织清楚、按需展示，避免同时堆出所有信息。沿用「确定 Scene 内容编辑的浅色工作台布局与操作方式」的白底、深色按钮、灰色层级与双工作区。

- A：视频下方只留一句摘要与操作；详情从右侧打开。观看最安静，详情会暂时遮住一部分画面。
- B：视频旁保留精简侧栏，以标签切换摘要、检查、建议；主要操作固定在底部。信息持续可达，占用横向空间。
- C：完整视频下方按需展开审阅面板。阅读宽度更大，展开时暂时遮住画面下部。

用户明确选择 A，B/C 保留作比较证据。正式实现以视频优先、底部简短摘要与接受入口、按需右侧审阅抽屉为结构基线。没有把原型写入生产设计体系或改变领域规范。

播放与当前／候选切换；查看摘要、检查及合成代表帧定位；Scene 建议定位、修改及返回；输入过期、构建阻断、非阻断警告；停止任务；接受、放弃确认；接受后输出；缺 Speech 允许接受、阻止输出；尚无候选。

全部内容、画面、标识、检查和输出均为合成模拟。画面是 Canvas 动画而非真实 Render Program 视频；没有音轨，不生成视频文件。刷新重置内存状态。表格仅模拟 Scene 3，不代替上一轮完整 Scene 原型。

# Design Token 第一版

出处：[Visual Type 四件套的视觉定稿](https://github.com/dulltackle/narracut/issues/8)、[静态图片如何进入 Visual 与 Asset 模型](https://github.com/dulltackle/narracut/issues/17)
原型：`prototypes/visual-types.prototype.html`（分支 `prototype/visual-types`）

V1 不做主题切换，但渲染器内部**必须**按这些 token 组织。把颜色字号硬写进组件，将来抽 Theme 就得重写全部组件——这是本文件存在的唯一理由。

画布固定 1920×1080 @ 30fps，所有像素值都是这个画布上的值。

---

## 1. 颜色：双轨制

配色不是一套，是两套，按**画面有没有素材**分工：

| 轨 | 用在哪 | 承担什么 |
|---|---|---|
| **品牌轨（粉）** | Title、EndCard——背景由我们完全控制 | 温暖、亲和、机构识别 |
| **临床轨（蓝）** | Image、Image+Caption、Video、Video+Caption 的叠加物——叠在亮度不可控的 Asset 上 | 专业、可信、可读 |

受众是医护，所以粉色只作品牌温度，不主导画面；正片一律走蓝。

### 品牌轨

| Token | 值 | 用途 |
|---|---|---|
| `--pink-50` | `#FDF2F5` | Title / EndCard 底色 |
| `--pink-100` | `#F9DDE6` | 底色上的柔光晕 |
| `--pink-300` | `#F0A6C0` | 左侧品牌色带的浅端 |
| `--pink-500` | `#E8628E` | 品牌主色：色带、Logo 底、EndCard 序号 |
| `--pink-700` | `#B83A66` | 浅底上的粉色文字（设备名） |

### 临床轨

| Token | 值 | 用途 |
|---|---|---|
| `--blue-500` | `#1E6FD9` | 步骤条左侧竖条 |
| `--blue-600` | `#1657AC` | 蓝色文字与深底 |
| `--blue-900` | `#0B2E5C` | 步骤条渐变衬底 |

### 警示轨

| Token | 值 | 用途 |
|---|---|---|
| `--amber-500` | `#F59E0B` | 警示边框与文字 |
| `--amber-700` | `#B26B00` | 深化用 |
| `--amber-ink` | `#3D2400` | 琥珀实底上的文字 |

**警示为什么是琥珀不是红**：主色一旦是粉，红色警示在色相上是粉的邻居，不再"跳"，只会看起来像"深一点的粉"。琥珀与临床蓝的色相差接近 180°，同时避开红绿色盲的雷区。

**警示不能只靠颜色**——实拍画面里本来就有红灯绿灯黄灯。三重区分缺一不可：**换色相 + 加图标 + 独立版面位置**。

### 中性（暖调）

| Token | 值 | 说明 |
|---|---|---|
| `--ink-900` | `#2A2226` | 正文深色。**带红调，不是纯黑**——纯黑配粉色会显冷 |
| `--ink-600` | `#6B5F65` | 次要文字 |
| `--ink-300` | `#C9BFC3` | 分隔线 |
| `--ink-0` | `#FFFFFF` | 实拍上的字幕与叠加文字 |

## 2. 字体

**Noto Sans SC / 思源黑体**，SIL OFL 授权，可自由打包分发。

硬约束（[02 — Remotion 实拍渲染调研](https://github.com/dulltackle/narracut/issues/7) 第 6 条）：必须 `loadFont()` 显式加载、字体文件放 `public/`、**禁止依赖系统字体**；自写的换行测量必须等字体 resolve。

字重收敛到 **三个**：`400 Regular` / `700 Bold` / `900 Black`。原本还用了 500 Medium，并入 400。三个字重由同一份可变字体提供，不需要各打包一份静态字体。

### 打包与字符覆盖

V1 打包官方完整的 `NotoSansCJKsc-VF.ttf`（约 34.5 MiB），放在 `public/fonts/`。这是一份简体中文可变 TTF，由同一个物理文件提供 `400`、`700`、`900` 三档字重。Player 与 renderer 必须通过同一个共享字体加载模块引用它，并各自等待该模块导出的 `loadFont()` Promise；不通过 Google Fonts 发起网络请求，也不依赖系统字体。

V1 **不做任何子集化**：不使用 GB2312 等静态区域子集，也不在打开项目、编辑文本或渲染前动态生成项目子集。因此不引入 `fonttools`、`subset-font` 或字体子集缓存/失效链路。

该文件的 cmap 覆盖范围就是 V1 的可渲染字符集合。进入 Player 或发起渲染前，必须校验全部可见文本；发现字体没有的字符时硬性失败，并至少报告 Scene、字段、原字符与 Unicode 码位。禁止回落到系统字体或其他未打包字体，也禁止静默显示豆腐块。错误在编辑器中的具体呈现方式不由本文件规定。

策略出处：[中文字体打包与子集化策略](https://github.com/dulltackle/narracut/issues/16)。

### 字号阶梯

字号按**手机可读**定，不是桌面。桌面看手机规格的字只是"字大了点"，反过来是"看不清"，风险不对称。

| Token | 值 | 字重 | 用在哪 |
|---|---|---|---|
| `--fs-display` | 104px | 900 | Title 操作主题 |
| `--fs-h1` | 76px | 900 | EndCard 标题 |
| `--fs-step` | 56px | 700 | 步骤名 / Title 副标题 |
| `--fs-subtitle` | 52px | 900 | 字幕 |
| `--fs-alert` | 50px | 700 | 警示文字 |
| `--fs-bullet` | 44px | 400 | EndCard 要点 |
| `--fs-device` | 40px | 400 | 设备名型号 |
| `--fs-label` | 34px | 700 | 步骤序号 / EndCard 序号 / Logo 文字 |

步骤名（56）刻意大于字幕（52）：步骤名是标题，必须占主导。

数字一律 `font-variant-numeric: tabular-nums`。

## 3. 字幕：B3 描边派

**定稿：白字 + 3px 描边 + 多层投影，不加任何底衬、不改画面。**

```css
.subtitle {
  font-size: 52px;
  font-weight: 900;
  color: #FFFFFF;
  paint-order: stroke fill;
  -webkit-text-stroke: 3px rgba(20, 14, 17, 0.94);
  text-shadow:
    0 0 6px rgba(20, 14, 17, 1),
    0 4px 14px rgba(20, 14, 17, 1),
    0 0 40px rgba(20, 14, 17, 0.85);
}
```

三处不能改动的细节：

- **`paint-order: stroke fill` 必须有。** 它让描边画在填充**之下**，只向外扩，不吃掉笔画本身。去掉这一行，描边会居中于字形轮廓，中文笔画会被啃细。
- **3px 是上限不是起点。** 52px 字号下 3px ≈ 5.8% em，落在广播字幕 4–6% em 的常规区间内。4px 起，密笔画字（灌、器、械、断）笔画之间的空隙开始被向外扩的描边填死。字号若变，描边按 em 比例换算，不要沿用 3px 这个绝对值。
- **投影三层是有分工的**：6px 收紧字缘、14px 给垂直分离、40px 是大范围压暗。少一层在高亮白面板上就顶不住。

已淘汰的两条路，不要回头：**A 底衬**（半透明圆角衬，画面被挖块）、**C 安全条**（底部实心色带，切掉画面）。

## 4. 间距、圆角、安全区

8 基数阶梯：`8 / 16 / 24 / 32 / 48 / 64 / 80 / 96`

| Token | 值 |
|---|---|
| `--r-sm` | 8px |
| `--r-md` | 16px |
| `--r-lg` | 28px |
| `--r-pill` | 999px |

**安全区 80px**（约画布 7.4%）。字幕基线距底 96px。警示条距底 300px——它落在字幕上方，两者版面关系是一起定的，不是各定各的。

## 5. 动效

只有 Cut，所以 Scene 之间是硬切，入场动效必须能在硬切下自然成立。

| Token | 值 |
|---|---|
| `--dur-fast` | 200ms |
| `--dur-base` | 320ms |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` |

**V1 只有一条动效规则**：

| 元素 | 动效 |
|---|---|
| 警示条 | 200ms 淡入 + 上移 16px |
| 步骤条 | **静止** |
| 字幕 | **静止** |
| Title / EndCard | **静止** |

警示条动，是因为它必须被注意到。别的都不动：步骤条是背景信息，动了抢戏；字幕每句都动会晕。

PRD 第 13 节那套 Motion Preset 体系（Entrance / Emphasis / Exit 三组预设）V1 不做。

## 6. 六个 Visual Type 的字段清单

> 这一节是给 [11 — DSL schema 定稿](https://github.com/dulltackle/narracut/issues/11) 的直接输入。字段名是提议，最终以 DSL 票为准；**字段的存在与否**则是本票定死的。

### `Title`（仅片头一块，无素材）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `device` | string | 是 | 设备名与型号，如「GX-3000 妇科诊断系统」 |
| `headline` | string | 是 | 操作主题 |
| `subheadline` | string | 否 | 副标题 |

Logo 不是 Scene 字段——它是项目级资产，四块板子共用，进项目元信息。

### `Video`（全屏实拍 + 字幕）

无独立内容字段。字幕文本直接取 `narration.text`，不重复存储。

### `Image`（全屏静态图片 + 字幕）

无独立内容字段。字幕文本直接取 `narration.text`，不重复存储；图片在整个 Scene Duration 内静止显示。

### `Video+Caption`（实拍 + 叠加物）

叠加物只有**两种语义**，用判别字段区分：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `captionKind` | `"step"` \| `"alert"` | 是 | 判别字段 |
| `stepNumber` | string | `kind=step` 时是 | 序号，如 `"02"`。存字符串不存数字——它是展示用编号，不参与计算，也可能出现 `"3a"` |
| `stepName` | string | `kind=step` 时是 | 步骤名 |
| `alertText` | string | `kind=alert` 时是 | 警示文字 |

### `Image+Caption`（静态图片 + 叠加物）

字段与 `Video+Caption` 完全相同，使用同一个 Step / Alert 判别模型；两者只通过所引用 Asset 的 `kind` 区分。

明确**不做**的：坐标定位、箭头、圈选、部件指认。那类需求靠拍摄时的镜头语言（推近、手指指）解决，不靠后期叠加——一旦引入坐标，DSL 要加坐标字段、编辑器要加画面打点交互，工程量是其余全部叠加物之和的数倍。

参数标注（「转速 3000 rpm」）并入 `stepName` 文本，不单独建类型。

### `EndCard`（结尾）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | string | 是 | 如「本节要点」 |
| `bullets` | string[] | 是 | 3–5 条要点回顾 |

`bullets` 是**独立手写字段**，编辑器不从步骤名预填、不与正文联动。用户改一个步骤名，片尾不跟着变。

## 7. 已定但值得记住的取舍

- **粉与蓝分居两端**是刻意的：片头片尾是"品牌"，正片是"临床"。若成片看下来断裂感明显，补救手段是让片头片尾出现少量蓝（如设备型号那行），而不是把粉带进正片。
- **每个 Visual Type 只有一种 Layout。** PRD 第 12 节的 Layout Preset 体系 V1 不做。
- **字幕只有一个位置、一种样式。** PRD 第 26 节的 Bottom/Center 与 Default/Highlight 两组选项 V1 不做。

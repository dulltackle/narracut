# 最终 Render：局部界面说明

本说明记录 #81 在既有 Operate 暗房工作台内增加的最终输出区域，以已实现代码为依据。范围限于最终 Render 的来源、准备、进度、恢复与产物反馈，不建立新的品牌规则或全局设计令牌。

## 既有系统与本次边界

界面复用根目录 `DESIGN.md` 的暗房底色、纸白正文、深校片蓝主操作、琥珀诊断、结构分隔线、中文字体、控件圆角和可见焦点。新增样式使用已有 CSS 自定义属性；标题、状态和技术详情分别采用已有字级（`1.08rem`、`0.84rem`、`0.79rem`）。区域沿用成片 Preview 的容器，未引入新卡片体系、装饰材质或字体。

本次属于既有系统的局部功能扩展，不修改全局视觉规范。`DESIGN.md` 与 `PRODUCT.md` 中“Render 尚未启用”等文字描述较早交付阶段；最终 Render 的本次范围以本说明和 #81 为准。

## 来源与准备

最终 Render 区域常驻于 Agent 工作区的成片 Preview 之后。桌面标题行左侧显示来源修订短标识、摘要及两个独立状态：“已接受 / 尚未接受”和“Render 就绪 / Render 已阻断”；右侧提供“准备最终 Render”。接受事实不会因 Render 失败被改写成未接受。

准备后展示时长、画幅、帧率及输出位置，用户通过宿主系统目录选择器选择输出文件夹，再显式开始 Render。Scene 或 Brief 尚未保存、存在冲突、身份不可确认等状态会禁用启动并解释原因。已准备状态与最新来源身份不一致时，要求重新准备。

正在查看的 Preview 与输出来源不一致时，独立显示提示和“查看目标修订”。只有用户点击才切换到已有的目标 Preview；目标不可用时说明需要构建并核对，不把当前画面冒充为目标来源。

## 进度、恢复与结果

执行中显示准备校验、离线重建、渲染帧、编码、验证发布等阶段；渲染帧阶段在获得真实计数时显示已完成帧数与总帧数。来源与输出位置绑定正在执行的任务，取消期间明确显示清理状态。

请求结果不确定时显示“核对 Render 状态”，核对完成前禁用重复启动。可重试失败提供“重试 Render”；阻断说明按已有定位信息引导返回表格处理 Scene/媒体问题，或前往候选检查与验收。

成功后展示实际文件名、完整输出路径与启动时来源修订；若期间项目已更新，明确说明产物属于启动时状态。文件定位使用宿主能力，不支持时复制实际路径并告知结果。不可变身份等技术数据放入默认折叠的原生“Render 详情”。

## 窄屏与交互连续性

`700px` 以下标题行与输出行纵向堆叠，对应操作按钮通栏。按钮和详情入口最小高度为 `44px`；长路径、诊断及技术详情换行，键盘焦点沿用可见蓝色轮廓。

状态刷新只更新现有节点的文字、显隐和禁用属性，同一挂载区域不重建内容；简短反馈通过 `role="status"` 与 `aria-live="polite"` 播报。Render 轮询不替换 Preview、Scene 编辑节点或 Composer，因此延续工作台的会话草稿与输入焦点保留方式。准备完成后焦点明确进入输出文件夹选择按钮。

## 实现证据

- `plugins/narracut/workbench-render.js`：来源与状态显示、准备、目录选择、启动、取消、核对、恢复及结果反馈。
- `plugins/narracut/workbench.html`：最终 Render 局部样式与窄屏规则。
- `plugins/narracut/workbench.js`：常驻区域、宿主调用、保存门禁及表格定位。
- `plugins/narracut/workbench-preview.js`：正在查看的修订识别与显式目标查看。

本说明基于代码审阅，不将尚未核对的视觉截图、运行测试或服务端保证记为已通过证据。最终 Render 的具体行列布局和阶段文案仅属于本功能，不升格为所有工作区必须继承的全局规则。

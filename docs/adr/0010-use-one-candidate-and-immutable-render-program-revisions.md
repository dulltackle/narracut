# 以单一候选和不可变修订管理 Render Program

> **状态：已接受。** 这是 [ADR-0008](./0008-project-vnext-normative-architecture.md) 的候选/修订边界 ADR。

## Decision

项目同时最多只有一个可写候选 Render Program。Agent、人工编辑器和外部工具共享这一个写入对象；每批成功修改原子替换候选，并换代一个只用于完整性恢复的候选恢复检查点。

用户整体接受候选时创建完整、不可变修订，原子改变单一当前指向并消费候选。项目保留最近 20 份已接受修订；回退从历史修订创建新候选并对最新输入重新验收。

Agent 创作任务以单一持久检查点记录最小可恢复状态，不保存对话、推理、日志或任务历史。一个任务由一个 Codex 创作线程驱动，同一时刻只有一个线程拥有候选写权。

## Considered Options

- **直接修改当前 Render Program**——被否。无法区分可见草稿、已接受状态和中断中的部分写入。
- **候选分支或候选历史**——被否。会产生多个可写真相，并把版本管理复杂度暴露给产品。
- **接受部分文件或直接移动历史指针**——被否。接受对象不再对应用户审核的完整视频状态，也会绕过最新输入验收。
- **从聊天记录恢复任务**——被否。聊天不是随项目移动的权威状态，且包含不应持久化的推理与工具输出。
- **唯一候选、换代检查点和不可变修订链**——采用。

## Consequences

- 接受、放弃和新目标接管是清晰的任务终结边界；停止只暂停自主动作并保留候选。
- 相同程序字节在不同项目输入下接受仍形成新修订。
- 外部候选变化保留外部字节、丢弃未提交 Agent 修改并停止任务，不自动合并。
- 当前指向、候选、恢复检查点、历史索引和任务检查点都必须使用明确原子提交点。

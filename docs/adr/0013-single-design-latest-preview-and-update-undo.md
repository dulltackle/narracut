# 单一画面设计、最新内容预览与单步更新撤回

> **状态：已接受，#122 已实施内容同步，#128 已分离画面撤回并接入恢复后同步；其余路径仍由后续工单实施。** 完整交互及实施规格统一见 [#121](https://github.com/dulltackle/narracut/issues/121)。本 ADR 记录对 ADR-0010 和预览展示规则的计划替代，首次 Agent 生成、画面调整、试听及单对话交接的完整落地仍按对应子工单验收。

用户希望视频直接对应最新表格内容，只面对一份画面设计，并可撤回更新选择。为减少候选比较和接受操作的负担，表格变化后停止展示旧视频，由用户选择“仅同步表格内容”或“同步内容并调整画面”；完整更新成功后直接使用结果，保留跨项目重开的最近一步撤回，撤回不撤销表格编辑。

## 取舍

### 后续设计修订：默认同步表格内容（待实现）

完整变更规格已发布为 [#127：默认同步表格内容、按 Scene 范围调整画面与独立画面撤回](https://github.com/dulltackle/narracut/issues/127)，以下记录已确认取舍；实施与验收以该规格为准。

用户后续确认：第一版数据层只承载用户在 Scene 中输入的内容；Codex 为画面推导的标题、图表数值等继续保存在 Render Program，不新增可由用户编辑的 Scene 画面数据字段。

表格修改后的默认行为改为仅同步表格内容，不改写 Render Program，也不调用 Codex。用户显式选择“同步内容并调整画面”时才准备并复制调整指令，由用户在当前 Codex 对话发送；复制本身不启动创作。本方向替代下文与 #121 中“每次编辑后等待用户选择更新方式”的设计要求，已发布变更规格，尚未修改生产实现。

已确认的触发与撤回规则：

- 表格保存成功且用户短暂停止编辑后自动同步，连续修改合并处理；同步期间再次编辑阻止旧输入发布，只同步最新内容。新 Speech 生成成功也触发同步，但同步本身不生成 Speech。没有画面设计时不自动创建设计，仍从当前对话明确授权首次生成。
- 自动同步不创建或替换用户可用的一步画面撤回。一步撤回只针对最近一次成功的 Codex 生成或画面调整，跨项目重开保留；表格编辑使用表格自身的撤销功能。
- 撤回画面调整后，恢复的设计自动同步最新表格内容，经检查成功后才展示视频，不播放旧内容。撤回首次生成后恢复无设计状态，不触发默认设计生成。不提供连续画面回退或重做。

已确认的调整范围与编辑规则：

- Codex 实际调整画面期间禁止用户修改整个表格；复制指令本身不表示创作已开始，也不锁定表格。
- 每次点击“同步内容并调整画面”后，显示以 Scene 序号和 Narration 摘要识别的勾选列表，支持不连续多选与全选，默认选中当前 Scene；确认范围后点击“复制调整指令”。指令以稳定 Scene ID 记录范围，不能因表格重排改指其他 Scene。
- 范围外的画面保持不变，包括共用样式、跨 Scene 动画与 Transition 可能产生的影响。若需要影响相邻 Scene 或全片，Codex 必须告知用户需要扩大的范围及原因，不能自行扩大修改范围；是否扩大由用户决定。

下文保留原有取舍供追溯；独立画面撤回与恢复后同步由 #128 实施，默认同步调度与 Scene 范围调整仍待对应子工单实施。

### #128：独立画面撤回

内容同步与画面创作使用独立持久记录。只有成功生成／调整建立或替换一步画面撤回；恢复设计先原子消费撤回，再自动检查并同步最新内容。后续同步失败不撤销已恢复事实，只重试同步。有限修订索引固定创作身份及恢复目标，继续纳入复制与恢复来源绑定；首次生成撤回不补建设计。该实现替代下文同步占用撤回、撤回等待选择的原有语义；默认同步调度和范围选择仍由后续工单实施。验收边界见 [#128 验收](../acceptance/issue128/README.md)。

### 原有取舍与实施依据

- 不再采用“旧预览标为过期但继续可看”：它允许用户看到与当前表格不一致的视频。更新期间、失败后及再次编辑后，宁可显示需要更新，也不展示不匹配内容。
- 不再采用用户比较当前／候选并明确接受的正常流程：用户只面对单一设计，成功更新直接生效，以一步撤回提供纠正选择的能力。
- 不直接暴露未完成修改：取消、失败或输入再次变化的工作不能成为可查看的最新视频；内部隔离及原子发布仍有必要，但不形成第二份用户可选设计。
- 不在每次编辑后自动重新创作：用户明确选择更新范围，避免把仅需同步内容的修改扩大为画面重做。Speech 生成成功同样等待用户选择，不记忆上次选择自动执行。

## 后果与不变边界

- 实施将替换 ADR-0010 的用户明确接受、当前／候选比较及面向用户的多修订回退流程；本票的一步撤回不等于恢复旧表格或播放旧内容视频。存量修订数据的处理不能由本 ADR 推断为允许直接删除。
- 画面创作结果与对应撤回记录需要一致的持久化发布边界。下一次成功生成／调整替换记录，内容同步、失败或取消不消费它；撤回一次后不提供连续回退或重做。
- ADR-0009 的内容／表现分工保留：“仅同步表格内容”不会改写程序独立编写的语义；画面调整仍由 Render Program 承载。
- ADR-0011 的不可变执行产物、输入绑定、执行隔离及 Preview／Render 一致性保留。最新输入可以使用新实例；不能绕过检查，把旧输入证据冒充新视频的有效证据。
- 缺 Speech 仍可使用明确标记且对应句无声的草稿预览，最终 Render 的完整 Speech 要求不放宽；更新成功不等于自动执行最终输出。
- 同项目的非控制对话不再提供业务只读操作，而是引导返回控制对话并提供明确接管。先撤销旧写权、核对在途操作和未保存内容、释放占用，才授予新控制权；不凭无响应超时抢占。
- 实施必须同步调整规范、领域词义、工具协议与测试，不能把这次改变简化为删除接受按钮或放宽写权限。设计文档不是生产验收证据。

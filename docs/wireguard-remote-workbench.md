# 通过 WireGuard 访问工作台

Narracut 的 HTTP 服务默认绑定 WireGuard 地址 `10.8.0.5`，首选端口为 `3579`。启动后应以 CLI 输出的“本地工作台”URL 为准；如果端口已被占用，服务会依次尝试到 `3678`：

```bash
pnpm start <项目路径>
```

本机与 WireGuard 对端都使用输出的 `http://10.8.0.5:<实际端口>` 地址。服务不额外监听 `127.0.0.1`，也拒绝 `0.0.0.0` 与 `::` 这类通配地址。

服务没有应用层鉴权，并且 API 不只提供媒体读取，还能保存项目、导入 Asset、生成 Speech 和发起渲染。因此，**所有能够访问该 WireGuard 接口的对端都必须被视为受信任主体**。不要把端口转发到公网或其他不受信网络。

如果当前机器没有 `10.8.0.5`，启动会明确失败。确需在其他环境运行时，可显式覆盖为该机器上可访问的具体地址，例如只供本机测试：

```bash
NARRACUT_HOST=127.0.0.1 pnpm start <项目路径>
```

工作台列表只允许请求 `/api/assets/thumbnail` 返回的首帧 JPEG，不应为缩略图请求 `/media/*.mp4`。打开完整 Asset 预览、选择视频 Scene 或实际播放仍会读取原 MP4，并受 WireGuard 链路带宽、往返时延和丢包影响；低码率 Preview Proxy 不在当前方案范围内。

## 网络排查

出现主动视频播放卡顿或无法访问时，应同时检查：

- WireGuard 对端能否访问 `10.8.0.5`，握手和路由是否正常；
- 防火墙是否允许 CLI 输出的实际端口；
- 链路延迟、丢包、Wi-Fi 稳定性和 TCP 重传是否异常；
- VPN 或 MTU 是否造成分片与丢包；
- 原视频是否为 fast-start MP4（`moov` 位于文件头）。

应用侧缩略图服务仍应保留，因为它从根源上避免了工作台列表对原视频的无意义读取。

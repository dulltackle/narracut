# 当前 Codex 对话的工作台面板

## 能力依据与入口

2026-09-10 的当前会话实际提供 `mcp__codex_app__open_in_codex`：`placement: "right"` 配合 `target: {type: "browser", url}`，省略 `threadId` 时由宿主定位调用对话。插件通过 `skills/narracut-workbench/SKILL.md` 使用该宿主工具，启动 `panel.mjs` 并打开其本地 URL。没有该工具时，在当前对话显示能力不足，等待重试。

当前对话 Shell 的 `CODEX_THREAD_ID` 为 `01a08ab9-8932-7f43-a960-eabfc9646c5c`；本轮用宿主 `read_thread` 核对了相同 ID、工作目录及 #93 请求。启动技能要求每次从当前对话核对来源，再把环境身份绑定到该面板进程。浏览器请求参数不能改变绑定；共享 stdio MCP 进程不借用其启动环境猜测当前调用者。

[OpenAI 插件概览](https://learn.chatgpt.com/docs/plugins)说明插件可以组合技能、MCP 与可选 UI；[UI 参考](https://developers.openai.com/plugins/reference)描述的是 UI 运行时接口，本轮未从中找到能保证 Codex 当前对话右侧位置与对话 ID 的契约。因此此入口使用会话中实际提供的宿主工具，不新增私有调用，也不把 MCP display mode、返回 HTML 或 UI 握手解释成桌面位置证据。

## 运行边界

- `panel.mjs` 监听随机回环端口，以随机秘密路径承载外壳、原有工作台资源和工具转发。校验 Host、Origin、JSON 内容类型，关闭缓存与 referrer，秘密 URL 不进入文档或 issue。
- 外壳复用原工作台的 MCP Apps 握手与工具操作；项目创建、打开、Scene 保存、Asset、Preview、接受与最终 Render 仍走同一项目服务与门禁。
- 面板向既有 UI 注入自有文件选择适配器，将 `selectDirectory`、`selectFile`、`selectFiles` 转发到本地系统选择工具；覆盖启动器、Asset 导入、Render 选址及恢复/LOCAL 导出。原生命令由固定种类生成，未执行用户提供的标题或 Shell。
- `get_workbench` 读取本次会话最新项目与任务状态。关闭页面不会释放项目或终结任务，重新打开相同 URL 不重新创建项目。用户结束进程才释放服务资源。
- 创建或打开的持久结果与面板展示独立。`prepared` 表示服务就绪，宿主 `queued` 表示请求排队，两者都不表示已显示。服务失败的原因在当前对话报告；页面加载失败保留“重试显示工作台”，只重新读取当前会话。
- 没有可核实对话时，生产 stdio 入口与面板拒绝项目写工具；提供只读检查与具体原因。仅内部测试调用可不配置对话上下文。既有表格编辑和渲染条件仍由原服务执行。
- 项目名保持可见，路径、项目 ID 与对话 ID 收进详情；面板使用当前对话 Composer，底部仅保留说明。Scene 表格首开，窄面板保留检查抽屉、Asset 管理与 Agent 审阅入口。

跨对话查看与明确接管见下节。共享 stdio 无法确认调用对话时仍走能力不足路径；绑定到当前对话的面板通过相同 MCP 工具桥执行项目操作。

当前工具明确禁用原生应用 API；尝试其通用文档列出的 `cua.listApps` 也返回函数不存在。Linux 文件选择由 `directory-picker.ts` 启动独立 Zenity 窗口，不是浏览器 DOM 或 HTML 文件输入。故浏览器自动化不能完成该系统窗口的点击与截图；不应通过模拟文件路径声称已经验收原生选择窗口。环境中存在 `/usr/bin/zenity`，`DISPLAY=:0`，`XDG_SESSION_TYPE=x11`。

## 跨对话只读会话与明确接管（#94）

仅打开已占用项目时，不申请交接、不释放租约、不停止旧任务。只读面板绑定规范化的物理目录与项目 ID，通过现有租约中的回环端点读取持有进程的最新状态。端点使用租约能力令牌鉴权，并逐项允许只读工具；Scene、Asset、Speech、Brief、候选、依赖协调、检查执行、交付确认、接受、Render、恢复及复制写操作默认拒绝。浏览器参数不能改变已核实的对话身份。

当前对话明确请求 project_control/takeover 时，旧进程先封闭新的写请求、使已接收请求的权限代次失效，再撤销创作驱动并等待旧 Turn 的中断回执。请求权限在持久提交边界再次核对；旧 Speech 等后台执行也会取消。只有旧操作收尾、旧租约释放后，新会话才通过独占创建取得同一物理目录的租约。失败保留阻断和具体原因，重复明确接管用于核对重试；并发申请仍由进程租约决定唯一获胜者。

仅接管保留候选及任务 ID，不发起或继续创作、不接受或放弃候选。明确发起或继续创作复用相同屏障，并在有可信身份时绑定当前 Codex 对话。插件技能提供同一面板 RPC 调用路径；没有可复用面板时用 panel.mjs --take-control。

两个工作区共用顶部权限提示，连接状态独立显示。状态轮询让新旧面板更新权限；状态无法确认时暂停编辑。失权后清除自动保存计时器，保留本地 Scene 与 Brief 草稿，提供逐 Scene 旁白对照、最新内容及复制入口。重新获得控制权先读取最新内容，用户手动提交核对后的草稿；旧回执不能覆盖失权后的界面状态。

只读面板保留 Scene、Asset、Brief 和已有审阅结果的浏览入口。Preview 的 view 仅为已就绪 Bundle 和媒体字节复制独立的内存绑定，使用当前面板 origin、独立实例 ID 和令牌；不启动构建，不增加接受证据。build、检查执行和 Render 在只读会话均被拒绝。只读绑定有数量上限，项目清理时释放；失去来源实例后只能显示过期状态。

验收入口：tests/workbench-panel.test.ts 覆盖双对话 MCP 桥、公开 HTTP、全类写请求拒绝、明确继续、失败重试、旧 Turn 与 Speech 迟到结果、独立进程租约和只读 Preview 绑定；tests/project-control-race.test.ts 在身份及基线的最后磁盘校验中触发交接，验证提交前撤权；tests/e2e/workbench-panel.spec.ts 覆盖顶部状态、只读构建禁用、草稿保留、重新获得权限后手动保存和窄屏溢出。以上使用可控宿主替身，不代表真实 Codex 双对话桌面操作的录像证据。

## 当前对话继续已停止任务（#96）

用户明确继续时，服务校验单一任务检查点及当前候选基线，保持任务 ID，绑定发出指令的当前对话，并重新读取项目内容。应用重启仅加载为已停止，不启动创作；旧 Turn 未提交的修改、工具调用及中间判断不属于恢复状态。重启或交接后旧工具审批已失效，继续时重新判断和申请审批，旧回执不能恢复执行。

跨对话继续复用控制权交接屏障。撤销旧驱动并等待持久批次完成后，必须核对磁盘仍是本驱动最后成功写入的检查点、候选仍是已完成批次的基线，才封存交接状态；候选已原子提交但检查点尚在收尾时保留该成果。不能用旧内存补写缺失、损坏或不一致的检查点。无效时保留原持久内容并报告 `TASK_CHECKPOINT_INVALID`；用户仍可明确用新目标、按当前候选基线建立新任务。

验证入口为 `tests/creation-task.test.ts`：覆盖原子候选提交前后停止、重启后明确继续、Codex 中断、最新 Brief、跨对话写权与迟到结果、审批中重启或主动停止、候选提交后暂停收尾的交接，以及交接前注入三类检查点故障。使用公开 MCP 工具与可控宿主替身验证稳定状态及持久内容，不依赖模型随机输出；不作为真实 Codex 桌面交互的验收证据。

# 当前 Codex 对话的工作台面板

## 能力依据与入口

打开、重试、接管项目或驱动当前对话创作时，使用[插件工作台技能](../plugins/narracut/skills/narracut-workbench/SKILL.md)。技能负责核对当前对话身份、启动 `panel.mjs`、调用实际可用的宿主面板工具及持续驱动创作步骤；构建与安装见[插件打包](plugin-packaging.md)。

面板创建结果与宿主展示结果分别核对：`prepared` 只表示服务就绪，`queued` 只表示宿主排队；实际显示需要观察页面与桌面位置。秘密面板 URL 只供当前会话使用，不进入文档、issue 或共享证据。

工作区、任务与控制权约束见[规范第 2 节](spec/project-vnext.md#2-产品边界与工作区)和[第 8 节](spec/project-vnext.md#8-agent-创作任务)。实现入口为[面板服务](../plugins/narracut/src/workbench-panel.ts)、[项目控制权](../plugins/narracut/src/project-control.ts)与[创作任务](../plugins/narracut/src/creation-task.ts)。

## 当前 Agent 直接驱动创作（#99 修复）

生产工作台使用 [CurrentConversationHost](../plugins/narracut/src/current-conversation-host.ts)，通过当前对话的面板 RPC 交换 `creation_step`。独立 `CodexAppServerHost` 只用于固定宿主探针与协议测试；生产创作不启动独立模型进程或向另一个 App Server 请求 `thread/resume`。

步骤的调用顺序、身份核对、图像审阅与回执处理统一按插件技能执行。排查协议时须区分步骤接收与持久提交：`received` 不表示已落盘或交付；步骤只驻留内存，不扩展项目任务检查点。只读会话无权读取步骤能力；停止或接管撤销的是 Narracut 步骤，并不证明桌面 Codex Turn 已被中断。

当前 RPC 通道不能订阅桌面的原生停止/退出事件，也不能在 Scene 待办满足后自行唤醒已经结束的 Agent Turn。已观察到宿主错误且仍可调用工具时，可以显式报告中断；服务重启则按检查点加载为已停止。这些行为不替代规范要求的真实宿主生命周期验收。

## 验收边界与待办

当前实测结论、失败记录与剩余场景统一见[当前对话完整流程验收](current-conversation-acceptance.md)。公开自动化入口见[文档入口](README.md#公开流程验证)；自动化使用的宿主替身不证明真实双对话、桌面位置、原生关闭/重开或应用重启。

#93 的创建、打开和重试入口完整桌面操作，以及真实系统文件选择与取消、可追溯桌面截图仍需补齐。Linux 选择窗口由独立 Zenity 进程提供，浏览器 DOM 或模拟路径不能证明该窗口可见或已经完成选择。页面截图也不能证明 Codex 外层右侧位置。

旧会话曾将 CUA 全局枚举超时定位到 Chrome 扩展标签枚举，直接连接内置浏览器仍能检查页面。复验时先读取本次工具能力；全局枚举失败不足以证明所有页面检查能力不可用。旧会话探针、临时素材验收及已实现工单说明按[历史追溯](README.md#历史追溯)读取，不作为当前宿主能力保证。

### 真实桌面关闭／重开复验步骤

1. 从当前 Codex 对话核实身份，按插件工作台技能打开测试项目，在本地保留秘密服务 URL，记录项目目录、Project ID 和当前 Task ID。
2. 在当前对话明确发起一项会修改候选资源的创作；在 Agent 工作区确认“运行中”，记录候选 baseline 和最后保存阶段。
3. 使用 Codex 右侧面板自身的关闭入口关闭工作台，保持 Codex 应用、当前创作和服务进程运行。不要发送“停止任务”，也不要终止服务。
4. 等待当前对话产生新的持久成果。通过同一服务 `get_workbench` 读取任务和候选，记录 Task ID、候选 baseline，以及候选目录中实际新增或修改的文件内容。
5. 在同一对话用 `open_in_codex` 重新打开原 URL；观察先同步再显示最新内容。核对 Project ID、Task ID、最新候选和控制权；确认没有新任务、自动播放、自动接受或自动 Render。
6. 从另一对话打开同一项目，核对“只读 · 项目由另一对话控制”与禁用写操作；原任务和控制权保持不变。
7. 分别以用户明确停止、Codex 中断、退出并重启应用进行对照。重开应显示实际停止原因和保留成果，只有明确继续才再次运行；记录每种情况的 Task ID 与原因。
8. 记录验收日期、Codex 版本、对话身份、截图路径、候选文件证据和每步结果。真实模型不可用、额度不足或无法操作桌面关闭入口时，将对应步骤标为“未执行”，不得用自动化替代通过。

真实桌面关闭／重开综合步骤尚未完成；本文提供复验流程，不声明宿主桌面验收通过。
